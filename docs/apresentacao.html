Prompt Store voltar ao README

Uma história de engenharia

Construir pequeno. Aprender o ciclo inteiro.

O Prompt Store é um laboratório para praticar engenharia de software do requisito ao deploy, usando um ecommerce simples de prompts como problema real.

Estado atual

O MVP já possui catálogo, compra com créditos, persistência SQLite, testes, observabilidade e proteção para um ambiente privado.

01 · O produto

Um domínio pequeno com regras importantes.

Cada prompt é um produto digital com título, descrição, conteúdo e preço inteiro em créditos. O usuário pré-configurado começa com 100 créditos e adquire prompts sem checkout ou pagamento externo.

Ver catálogo → verificar saldo → adquirir → debitar → registrar → liberar conteúdo. O débito e a aquisição precisam acontecer juntos. Uma falha não pode deixar saldo alterado sem acesso, nem acesso sem débito.

02 · A solução atual

Tecnologia a serviço do aprendizado.

As escolhas foram feitas para reduzir complexidade incidental e deixar visíveis as decisões essenciais do produto.

Aplicação

Ruby on Rails 8

Framework web convencional para acelerar CRUD, rotas, views, migrações, testes e segurança básica.

Interface

HTML server-side

Views Rails e CSS local. Evita uma SPA e uma segunda cadeia de build enquanto o domínio ainda é pequeno.

Dados

SQLite + Active Record

Persistência simples para uma instância e baixo volume, com migrações, constraints e transações.

Catálogo

JSON versionado

Separa dados de implementação sem exigir painel administrativo ou banco para leitura dos produtos.

Qualidade

Minitest, RuboCop e Brakeman

Testes comportamentais, estilo consistente e análise estática de segurança.

Operação

Logs, métricas e health checks

Logs JSON, request IDs, métricas internas e endpoints para saber se processo e banco estão prontos.

Execução

Docker Compose

Imagem multi-stage, usuário não-root e volume persistente para executar o MVP de forma reproduzível.

03 · Fases de engenharia

O que cada fase significa.

As fases não são caixas isoladas. Cada wave percorre um pequeno ciclo completo e pode fazer o projeto voltar a uma fase anterior.

1

Descoberta e especificação

Entender o problema antes da tecnologia. Define atores, objetivos, requisitos, não objetivos, critérios de aceitação, riscos e perguntas abertas.

2

Projeto

Escolher responsabilidades, dados, interfaces e arquitetura. A pergunta central é: qual é a menor solução que atende ao risco atual?

3

Implementação

Transformar o projeto em incrementos pequenos, explícitos e revisáveis, mantendo documentação e histórico próximos do comportamento.

4

Validação e testes

Verificar comportamento feliz, erros, limites, repetição e falhas. Testar não é apenas executar o código: é produzir evidência.

5

Entrega e operação

Construir, publicar, observar, diagnosticar e reverter. Um software que funciona localmente ainda não é um produto operável.

6

Segurança e manutenção

Reduzir exposição, proteger dados, atualizar dependências, fazer backup, responder a incidentes e revisar dívidas.

05 · Evidência de qualidade

Definition of Done não é “parece funcionar”.

Cada wave precisa deixar uma forma de verificar o comportamento e uma explicação sobre os riscos aceitos.

  • Requisitos e critérios de aceitação localizáveis
  • Testes cobrindo o risco relevante
  • RuboCop sem offenses
  • Brakeman sem warnings
  • Bundler Audit sem vulnerabilidades conhecidas
  • Smoke test contra o servidor real
  • Decisão técnica registrada em ADR
  • Limitações e próximo passo explícitos

06 · Aprendizados

O processo também é o produto.

Framework não substitui entendimento

Geradores Rails aceleram o início, mas cada migration, model, controller, view e teste precisa ser relacionado a um requisito.

Erros de integração são evidência

Testes encontraram problemas de autoload, associação Active Record e logger de produção antes do deploy.

Segurança depende do contexto

Uma conta compartilhada pode ser aceitável em um MVP privado, mas não deve ser confundida com um ecommerce público.

Observabilidade tem limites

Métricas em memória ajudam a aprender, mas exigem retenção, alertas e proteção antes de uma operação real.
